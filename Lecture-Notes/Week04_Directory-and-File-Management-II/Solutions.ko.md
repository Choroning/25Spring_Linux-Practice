## 연습 문제 1: 디렉터리 복사

**문제:** `project/` 디렉터리 전체와 그 내용을 `/backup/`으로 올바르게 복사하는 명령어는?

- A. `cp project/ /backup/`
- B. `cp -r project/ /backup/`
- C. `cp -f project/ /backup/`
- D. `cp -l project/ /backup/`

### 풀이

**정답:** B. `cp -r project/ /backup/`

**해설:** `-r`(recursive) 옵션은 디렉터리와 그 안의 모든 내용을 복사하는 데 필요하다. `-r` 없이 디렉터리를 주면 `cp`는 `cp: -r not specified; omitting directory 'project/'` 메시지를 내고 그 디렉터리를 건너뛴다. `-f` 옵션은 대상 파일을 강제로 덮어쓰게 할 뿐 재귀 복사를 켜지 않는다. `-l` 옵션은 파일을 복사하는 대신 하드 링크를 만드는 옵션이며, 역시 `-r` 없이는 디렉터리를 건너뛴다.

## 연습 문제 2: 하드 링크 vs. 심볼릭 링크

**문제:** 하드 링크에 대한 다음 설명 중 **틀린** 것은?

- A. 하드 링크는 원본 파일과 동일한 inode 번호를 공유한다.
- B. 원본 파일을 삭제하면 하드 링크가 댕글링 링크가 된다.
- C. 하드 링크는 서로 다른 파일 시스템 사이에 생성할 수 없다.
- D. 하드 링크는 디렉터리에 대해 생성할 수 없다.

### 풀이

**정답:** B. 원본 파일을 삭제하면 하드 링크가 댕글링 링크가 된다.

**해설:** 하드 링크는 원본과 같은 inode를 공유하므로, 하드 링크가 하나라도 남아 있는 한 파일의 데이터는 유지된다. 원본이라 부르던 이름을 삭제해도 디렉터리 항목 하나가 제거되고 링크 수가 1 줄어들 뿐이며, 데이터는 링크 수가 0이 될 때만 해제된다. 대상 파일이 삭제되었을 때 댕글링(끊어진) 링크가 되는 것은 심볼릭 링크이다.

## 연습 문제 3: I/O 리다이렉션

**문제:** 출력 리다이렉션에서 `>`와 `>>`의 차이점은?

- A. `>`는 파일에 추가하고, `>>`는 파일을 덮어쓴다.
- B. `>`는 파일을 덮어쓰고, `>>`는 파일에 추가한다.
- C. `>`와 `>>` 모두 파일을 덮어쓴다.
- D. `>`는 stdout에 쓰고, `>>`는 stderr에 쓴다.

### 풀이

**정답:** B. `>`는 파일을 덮어쓰고, `>>`는 파일에 추가한다.

**해설:** `>` 연산자는 출력을 파일로 리다이렉션하며, 파일이 없으면 만들고 있으면 내용을 비운 뒤(덮어쓰기) 쓴다. `>>` 연산자도 출력을 리다이렉션하지만 파일의 끝에 추가하므로 기존 내용이 보존된다. 예를 들어 `echo "line1" > log.txt`로 파일을 만든 뒤 `echo "line2" >> log.txt`를 실행하면 line1을 지우지 않고 두 번째 줄이 추가된다.

## 연습 문제 4: grep과 정규 표현식 사용

**문제:** `/etc/passwd`에서 문자열 `root`로 시작하는 모든 줄을 표시하는 명령어는?

- A. `grep "root$" /etc/passwd`
- B. `grep "^root" /etc/passwd`
- C. `grep "*root" /etc/passwd`
- D. `grep "root" /etc/passwd`

### 풀이

**정답:** B. `grep "^root" /etc/passwd`

**해설:** `^` 앵커는 줄의 시작에 일치하므로 `^root`는 root로 시작하는 줄에 일치한다. 선택지 A는 줄의 끝에 일치하는 `$`를 사용하므로 root로 끝나는 줄을 찾는다. 선택지 C의 `*`는 정규 표현식에서 앞 문자의 0회 이상 반복을 뜻하는데, 패턴 맨 앞에서는 반복할 앞 문자가 없으므로 기본 정규 표현식에서 문자 `*` 자체로 취급된다. 따라서 `*root`라는 문자열이 들어 있는 줄만 찾으며, 셸 글로빙의 와일드카드처럼 임의의 문자열을 뜻하지 않는다. 선택지 D는 줄의 시작뿐 아니라 어디에 있든 root에 일치한다.

## 연습 문제 5: find로 파일 찾기

**문제:** `/var` 아래에서 50 MB보다 큰 모든 `.log` 파일을 찾는 명령어를 작성하라.

### 풀이

**정답:** `find /var -name "*.log" -size +50M`

**해설:** `find` 명령어는 지정한 경로부터 재귀적으로 검색한다. `-name "*.log"`는 파일 이름 패턴으로 거르고, `-size +50M`은 50 MiB(1 MiB = 1,048,576바이트)보다 큰 파일을 거른다. `+` 접두사는 보다 크다는 뜻이다. 패턴을 따옴표로 감싸야 셸이 `*.log`를 먼저 확장하지 않는다. `-type f`를 추가하여 검색을 일반 파일로 제한할 수도 있다.

## 연습 문제 6: 파이프 사용

**문제:** 다음 명령어는 무엇을 하는가?

```bash
cat /etc/passwd | sort | head -5
```

- A. `/etc/passwd`의 처음 5줄을 원래 순서로 표시한다.
- B. `/etc/passwd`의 마지막 5줄을 알파벳 순으로 표시한다.
- C. `/etc/passwd`의 모든 줄을 알파벳 순으로 정렬한 뒤 처음 5줄을 표시한다.
- D. `/etc/passwd`를 정렬하고 처음 5줄을 파일에 저장한다.

### 풀이

**정답:** C. `/etc/passwd`의 모든 줄을 알파벳 순으로 정렬한 뒤 처음 5줄을 표시한다.

**해설:** 파이프(`|`)는 한 명령어의 stdout을 다음 명령어의 stdin으로 전달한다. 먼저 `cat /etc/passwd`가 파일 내용을 출력한다. 그다음 `sort`가 모든 줄을 알파벳 순으로 정렬한다. 마지막으로 `head -5`가 정렬된 출력에서 처음 5줄만 가져와 화면에 표시한다. 파일의 처음 5줄을 골라 정렬하는 것이 아니라, 전체를 정렬한 결과의 처음 5줄이라는 점에 주의한다. `sort /etc/passwd | head -5`도 같은 결과를 낸다.

## 연습 문제 7: tee 사용

**문제:** `ls -la`의 출력을 화면에서 보면서 동시에 `filelist.txt`에 저장하고 싶다. 어떤 명령어를 사용해야 하는가?

### 풀이

**정답:** `ls -la | tee filelist.txt`

**해설:** `tee` 명령어는 표준 입력에서 읽어 표준 출력(화면)과 하나 이상의 파일에 동시에 기록한다. `tee` 없이는 출력을 보거나(`ls -la`) 저장하거나(`ls -la > filelist.txt`) 둘 중 하나만 할 수 있다. 덮어쓰지 않고 추가하려면 `tee -a filelist.txt`를 사용한다.

## 연습 문제 8: stderr 리다이렉션

**문제:** `find / -name "*.conf"`의 오류 메시지만 `errors.txt` 파일로 리다이렉션하고, 정상 출력은 화면에 표시하는 명령어는?

- A. `find / -name "*.conf" > errors.txt`
- B. `find / -name "*.conf" 2> errors.txt`
- C. `find / -name "*.conf" &> errors.txt`
- D. `find / -name "*.conf" 1> errors.txt`

### 풀이

**정답:** B. `find / -name "*.conf" 2> errors.txt`

**해설:** 파일 디스크립터 2는 stderr를 나타낸다. `2>`를 사용하면 오류 메시지(`Permission denied` 등)만 지정한 파일로 리다이렉션되고, 정상 출력(stdout, 파일 디스크립터 1)은 계속 화면에 표시된다. 선택지 A는 stderr가 아니라 stdout을 리다이렉션한다. 선택지 C는 stdout과 stderr를 모두 리다이렉션한다. 선택지 D는 파일 디스크립터 1을 명시하여 stdout을 리다이렉션하므로 A와 같다.
