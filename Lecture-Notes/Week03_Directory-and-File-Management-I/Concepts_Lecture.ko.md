## 1. Linux 파일과 디렉터리

### 1.1 모든 것은 파일이다

**파일(file)** 은 관련 있는 정보의 집합이다. Linux에서는 장치와 디렉터리를 포함하여 거의 모든 것이 파일로 취급된다. 디렉터리도 파일의 한 종류로서 그 안에 저장된 파일과 하위 디렉터리에 대한 정보를 담고, 하드디스크나 키보드 같은 장치도 장치 파일로 다룬다. 또 Linux에서 확장자는 관례일 뿐 파일의 종류를 정하지 않으므로, 확장자가 없는 파일도 많다.

### 1.2 파일 유형

| 유형 | `ls -l`에서의 기호 | 설명 |
|------|-------------------|------|
| 일반 파일 | `-` | 텍스트 파일, 실행 파일, 이미지, 데이터 파일 |
| 디렉터리 | `d` | 다른 파일 및 디렉터리에 대한 참조를 포함 |
| 심볼릭 링크 | `l` | 원본 파일을 다른 이름으로 가리키는 파일 (Windows 바로가기와 유사) |
| 블록 장치 | `b` | 블록 단위로 읽고 쓰는 장치 (예: 하드 디스크 `/dev/sda`) |
| 문자 장치 | `c` | 문자 단위로 읽고 쓰는 장치 (예: 키보드, 터미널) |
| 파이프 | `p` | 프로세스 간 통신을 위한 이름 있는 파이프 |
| 소켓 | `s` | 프로세스 간 통신에 쓰는 소켓 파일 (Unix 도메인 소켓) |

*표 1. Linux의 파일 유형과 ls -l의 표시 기호*

### 1.3 파일 유형 식별

`file` 명령은 파일의 내용을 검사하여 그 종류를 알려 준다.

```bash
# 'file' 명령어를 사용하여 파일 유형 확인
$ file .profile
.profile: ASCII text

$ file /bin/bash
/bin/bash: ELF 64-bit LSB pie executable, x86-64

$ file /home
/home: directory
```

`file`은 확장자를 보지 않고 파일 앞부분의 바이트를 미리 알려진 형식의 표지(매직 넘버)와 비교하여 종류를 판정한다. 예를 들어 실행 파일은 `0x7F E L F` 네 바이트로 시작하므로 이름을 `photo.jpg`로 바꾸어도 `file`은 여전히 ELF 실행 파일이라고 판정하고, 텍스트 파일의 이름을 `a.png`로 바꾸어도 `ASCII text`라고 판정한다. 1.1절에서 확장자가 파일의 종류를 정하지 않는다고 한 것이 바로 이 뜻이다.

### 1.4 디렉터리의 실체와 링크 수

디렉터리 파일의 내용은 "이름과 inode 번호"의 쌍을 나열한 표이다. inode는 파일의 크기, 소유자, 권한, 시간, 데이터 블록의 위치를 담은 자료 구조이며(4주차), 파일의 이름은 inode가 아니라 그 파일을 담은 디렉터리의 표에 들어 있다. 모든 디렉터리의 표에는 자기 자신을 가리키는 `.`과 부모 디렉터리를 가리키는 `..`이 반드시 들어 있고, 루트 디렉터리의 `..`은 루트 자신을 가리킨다.

```text
디렉터리 /home/user1/ch2/d1의 내용 (이름 → inode 번호)
┌──────┬──────────┐
│ .    │ 1310722  │ ← d1 자신
│ ..   │ 1310721  │ ← 부모 ch2
│ a    │ 1310723  │
│ b    │ 1310724  │
│ c    │ 1310725  │
│ f    │ 1310726  │
└──────┴──────────┘
```

*그림 1. 디렉터리 파일에 저장된 이름과 inode 번호의 표*

`ls -l`의 둘째 필드인 링크 수는 그 inode를 가리키는 이름의 개수이다. 디렉터리 `d1`을 가리키는 이름은 부모 디렉터리 표의 `d1`, 자기 표의 `.`, 그리고 하위 디렉터리마다 그 표에 있는 `..`이다. 따라서 ext4 같은 Linux 파일 시스템에서 디렉터리의 링크 수는 다음과 같다.

```math
\text{디렉터리의 링크 수} = 2 + (\text{바로 아래 하위 디렉터리의 수})
```

하위 디렉터리 `a`, `b`, `c`와 일반 파일 `f`를 담은 `d1`에서 확인하면 다음과 같다(Ubuntu 24.04, ext4).

```text
$ ls -la d1
total 20
drwxrwxr-x 5 user1 user1 4096 Mar 21 12:05 .
drwxrwxr-x 3 user1 user1 4096 Mar 21 12:05 ..
drwxrwxr-x 2 user1 user1 4096 Mar 21 12:05 a
drwxrwxr-x 2 user1 user1 4096 Mar 21 12:05 b
drwxrwxr-x 2 user1 user1 4096 Mar 21 12:05 c
-rw-rw-r-- 1 user1 user1    0 Mar 21 12:05 f
```

- `.`(곧 `d1`)의 링크 수는 2 + 3 = 5이다. 일반 파일 `f`는 `..`을 갖지 않으므로 링크 수에 영향을 주지 않는다.
- 하위 디렉터리가 없는 `a`, `b`, `c`의 링크 수는 2 + 0 = 2이다.
- `..`(곧 `ch2`)은 하위 디렉터리로 `d1` 하나만 가지므로 3이다.
- ext4에서 디렉터리의 크기는 이름의 표를 담는 블록의 크기이므로 항목이 적으면 한 블록인 4096바이트이다. 디렉터리의 크기는 그 안에 든 파일들의 크기의 합이 아니다.

> **주의:** "디렉터리의 링크 수 = 2 + 하위 디렉터리 수"는 ext4처럼 `.`과 `..`을 실제 항목으로 두는 Unix 계열 파일 시스템의 규칙이다. macOS의 APFS처럼 다른 방식으로 링크 수를 보고하는 파일 시스템에서는 성립하지 않는다.

### 1.5 장치 파일

장치 파일은 데이터 블록을 갖지 않고, 커널 안의 장치 드라이버를 가리키는 두 개의 번호만 갖는다. **주 번호(major number)** 는 어느 드라이버가 이 장치를 맡는지를, **부 번호(minor number)** 는 그 드라이버가 다루는 여러 장치 가운데 어느 것인지를 나타낸다. `ls -l`은 장치 파일의 크기 자리에 `주, 부` 번호를 출력한다.

```text
$ ls -l /dev/sda /dev/sda1 /dev/null /dev/zero /dev/tty
brw-rw---- 1 root disk 8, 0 Mar 21 09:00 /dev/sda
brw-rw---- 1 root disk 8, 1 Mar 21 09:00 /dev/sda1
crw-rw-rw- 1 root root 1, 3 Mar 21 09:00 /dev/null
crw-rw-rw- 1 root root 1, 5 Mar 21 09:00 /dev/zero
crw-rw-rw- 1 root tty  5, 0 Mar 21 09:00 /dev/tty
```

- `/dev/sda`(첫 번째 SCSI, SATA 디스크)와 그 첫 파티션 `/dev/sda1`은 주 번호 8을 함께 쓰고 부 번호로 디스크 전체와 파티션을 구분하는 블록 장치이다. 디스크 장치의 이름 규칙은 10주차에서 다룬다.
- `/dev/null`은 쓰는 내용을 모두 버리고 읽으면 곧바로 파일의 끝을 돌려주는 문자 장치로, 필요 없는 출력을 버릴 때 쓴다(`명령 2> /dev/null`, 4주차).
- `/dev/zero`는 읽을 때마다 0 바이트를 끝없이 돌려준다. 정해진 크기의 빈 파일을 만들 때 쓴다(15주차의 `dd`).
- `/dev/tty`는 지금 프로세스가 연결된 터미널을 가리킨다.

블록 장치는 커널이 블록 단위로 버퍼링하여 임의의 위치를 읽고 쓰는 장치이고, 문자 장치는 바이트의 흐름으로 차례대로 읽고 쓰는 장치이다. 장치 파일의 권한(7주차)이 곧 그 장치에 대한 접근 권한이므로, 디스크 `/dev/sda`는 root와 `disk` 그룹만 읽고 쓸 수 있고 `/dev/null`은 모든 사용자가 쓸 수 있다.

## 2. 디렉터리 계층 구조

### 2.1 디렉터리 트리

Linux의 디렉터리는 루트 디렉터리를 꼭대기로 하는 트리 형태의 계층 구조를 이룬다.

- **루트 디렉터리(root directory):** 계층 구조의 최상위 디렉터리이며 `/`로 표시한다.
- **서브디렉터리(subdirectory):** 특정 디렉터리의 아래에 있는 디렉터리이다.
- **부모 디렉터리와 자식 디렉터리:** 어떤 디렉터리의 바로 위 디렉터리를 부모 디렉터리(상위 디렉터리), 바로 아래 디렉터리를 자식 디렉터리(하위 디렉터리)라 한다.
- **작업 디렉터리(working directory):** 현재 작업 중인 디렉터리이며 `pwd` 명령으로 확인한다.
- **홈 디렉터리(home directory):** 사용자 계정에 할당된 기본 디렉터리로, 로그인하면 처음 작업 디렉터리가 된다.

```text
/                          # 루트 디렉터리 (계층 구조의 최상위)
├── bin/                   # 필수 사용자 명령어 바이너리 (-> /usr/bin)
├── boot/                  # 부트 로더 파일 (커널, initramfs)
├── dev/                   # 장치 파일
├── etc/                   # 시스템 설정 파일
├── home/                  # 사용자 홈 디렉터리
│   ├── user1/
│   └── user2/
├── lib/                   # 필수 공유 라이브러리
├── media/                 # 이동식 미디어 마운트 지점
├── mnt/                   # 임시 마운트 지점
├── opt/                   # 선택적/추가 패키지
├── proc/                  # 프로세스/커널 정보용 가상 파일 시스템
├── root/                  # Root 사용자의 홈 디렉터리
├── run/                   # 실행 중인 서비스의 런타임 데이터
├── srv/                   # 서비스 데이터 (FTP, 웹)
├── sys/                   # 커널 및 장치 정보
├── tmp/                   # 임시 파일 (재부팅 시 삭제됨)
├── usr/                   # Unix 시스템 자원
│   ├── bin/               # 사용자 명령어
│   ├── lib/               # 라이브러리
│   └── local/             # 로컬 설치 소프트웨어
└── var/                   # 가변 데이터 (로그, 스풀, 캐시)
    └── log/               # 시스템 로그 파일
```

*그림 2. Linux의 디렉터리 트리*

Ubuntu는 `/bin`, `/sbin`, `/lib`를 각각 `/usr/bin`, `/usr/sbin`, `/usr/lib`를 가리키는 심볼릭 링크로 둔다. 그림 2의 `-> /usr/bin`이 이 관계를 나타내며, `ls -F /`로 보면 `bin@`처럼 이름 뒤에 `@`가 붙는다.

### 2.2 주요 디렉터리

| 디렉터리 | 용도 | 비고 |
|----------|------|------|
| `/` | 파일 시스템의 루트 | 모든 것이 여기서 시작됨 |
| `/home` | 사용자 홈 디렉터리 | 각 사용자는 `/home/username`을 가짐 |
| `/etc` | 설정 파일 | 시스템 전체 설정 |
| `/var` | 가변 데이터 | 로그, 메일, 데이터베이스 |
| `/tmp` | 임시 파일 | 재부팅 시 삭제됨 |
| `/proc` | 프로세스 정보 | 가상 파일 시스템 (메모리에만 존재) |
| `/usr` | Unix 시스템 자원 | 기본 실행 파일, 라이브러리, 헤더 파일, 문서 |
| `/root` | Root 사용자 홈 | `/`(루트 디렉터리)와 다름 |
| `/lost+found` | 복구된 파일 | 파일 시스템에 문제가 생겨 복구할 때 문제가 된 파일이 저장되며, 보통 비어 있음 |

*표 2. 주요 디렉터리의 용도*

> **참고:** usr를 Unix System Resources의 약자로 풀이하기도 하지만, 원래는 초기 Unix에서 사용자(user)의 홈 디렉터리를 두던 곳이라 붙은 이름이다.

> **핵심:** `/proc`는 하드 디스크에 저장되지 않고 커널이 메모리 상에서 만들어 보여 주는 가상 파일 시스템이다. 실시간 커널 및 프로세스 정보를 제공한다.

### 2.3 파일 시스템 계층 표준 (FHS)

> **용어 정의:** **파일 시스템 계층 표준(Filesystem Hierarchy Standard, FHS)** 은 Linux 배포판이 어떤 종류의 파일을 어느 디렉터리에 두어야 하는지 정한 표준이다. Linux의 `hier(7)` 매뉴얼 페이지는 2015년 3월 19일에 공개된 3.0판을 바탕으로 각 디렉터리를 설명한다 [1].

FHS는 디렉터리를 정할 때 파일을 두 가지 기준으로 나눈다. 하나는 여러 컴퓨터가 함께 쓸 수 있는지(공유 가능, 공유 불가)이고, 다른 하나는 실행 중에 바뀌는지(정적, 가변)이다 [2]. 예를 들어 `/usr`는 여러 Linux 컴퓨터가 함께 마운트할 수 있도록 공유 가능하고 읽기 전용인 자료만 담아야 하며, `/var`는 로그와 스풀처럼 크기가 바뀌는 파일을 담는다 [1]. 이 기준을 알면 처음 보는 디렉터리의 용도도 짐작할 수 있다.

| | 공유 가능 | 공유 불가 |
|:-----|:-----|:-----|
| **정적** | `/usr`, `/opt` (프로그램과 라이브러리) | `/etc`, `/boot` (그 컴퓨터의 설정과 부트 파일) |
| **가변** | `/var/mail` (사용자 메일함) | `/var/log`, `/run` (그 컴퓨터의 로그와 실행 상태) |

*표 3. 공유 여부와 변경 여부로 본 디렉터리의 분류*

표 2에 없는 디렉터리의 용도는 다음과 같다 [1].

| 디렉터리 | 용도 |
|:-----|:-----|
| `/boot` | 부트 로더가 쓰는 정적 파일 (커널 이미지, initrd) |
| `/dev` | 장치 파일 (1.5절) |
| `/media` | CD, DVD, USB 메모리 같은 이동식 매체의 마운트 지점. Ubuntu Desktop은 USB 메모리를 꽂으면 `/media/사용자이름/볼륨이름`에 자동으로 마운트함 |
| `/mnt` | 관리자가 파일 시스템을 임시로 마운트하는 지점 |
| `/opt` | 정적 파일로 이루어진 추가 소프트웨어 패키지 |
| `/run` | 부팅 뒤 시스템의 상태를 담은 파일 (PID 파일 등). 예전의 `/var/run`을 대신함 |
| `/srv` | 이 시스템이 제공하는 서비스의 데이터 (웹 서버, FTP 서버의 파일) |
| `/sys` | 커널과 장치의 정보를 구조적으로 보여 주는 가상 파일 시스템 sysfs의 마운트 지점 |
| `/usr/local` | 그 컴퓨터에서 직접 설치한 프로그램. 배포판의 패키지 관리자가 건드리지 않음 |
| `/var/tmp` | `/tmp`처럼 임시 파일을 두지만, 재부팅해도 지워지지 않아 오래 둘 임시 파일에 씀 |

*표 4. 그 밖의 주요 디렉터리*

`/tmp`의 파일은 주기적인 작업이나 부팅할 때 예고 없이 지워질 수 있다 [1]. Ubuntu 24.04는 부팅할 때 `/tmp`의 내용을 비우므로 [3], 다시 부팅한 뒤에도 남아야 하는 임시 파일은 `/var/tmp`나 홈 디렉터리에 두어야 한다.

## 3. 절대 경로와 상대 경로

### 3.1 절대 경로

- **항상 `/`로 시작한다.** `/`는 루트 디렉터리이다.
- 루트 디렉터리부터 대상 파일이나 디렉터리까지 거치는 중간 디렉터리의 이름을 모두 적는다.
- 현재 디렉터리와 관계없이 항상 같은 위치를 가리킨다.

```text
/home/user1/Documents/report.txt
/etc/hostname
/usr/bin/ls
```

### 3.2 상대 경로

- **`/`로 시작하지 않는다.**
- 현재 작업 디렉터리를 기준으로 한다. 하위 디렉터리로 내려갈 때는 그 디렉터리 이름으로 바로 시작하고, 상위 디렉터리로 올라갈 때는 `..`으로 시작한다.
- `.`(현재 디렉터리)과 `..`(상위 디렉터리)를 사용하며, 같은 대상이라도 현재 디렉터리에 따라 상대 경로가 달라진다.

```text
# 현재 디렉터리가 /home/user1인 경우
Documents/report.txt        # /home/user1/Documents/report.txt와 동일
../user2/file.txt           # /home/user2/file.txt와 동일
./script.sh                 # /home/user1/script.sh와 동일
```

예를 들어 현재 디렉터리가 `/usr/lib`이면 `/usr/bin/ls`는 상대 경로 `../bin/ls`로 가리킬 수 있다.

### 3.3 특수 디렉터리 기호

| 기호 | 의미 | 예시 |
|------|------|------|
| `.` | 현재 디렉터리 | `./script.sh` |
| `..` | 상위 디렉터리 | `cd ..` |
| `~` | 홈 디렉터리 | `cd ~` 또는 `cd` |
| `~user` | 다른 사용자의 홈 | `cd ~user2` |
| `-` | 이전 디렉터리 | `cd -` |

*표 5. 특수 디렉터리 기호*

### 3.4 경로 해석 규칙

커널이 경로를 파일로 바꾸는 과정을 **경로 해석(path resolution)** 이라 한다. 경로가 `/`로 시작하면 루트 디렉터리에서, 그렇지 않으면 현재 작업 디렉터리에서 출발하여, `/`로 나뉜 이름을 하나씩 그 디렉터리의 표(1.4절)에서 찾아 다음 디렉터리로 옮겨 간다. 이 과정에서 다음 규칙이 적용된다.

1. `/`가 여러 개 이어지면 하나로 본다. `/usr//bin`은 `/usr/bin`과 같다.
2. `.`은 지금 디렉터리에 머무르고, `..`은 부모 디렉터리로 옮겨 간다. 루트에서의 `..`은 루트이므로 `/..`과 `/../..`은 모두 `/`이다.
3. 중간의 이름은 모두 디렉터리(또는 디렉터리를 가리키는 심볼릭 링크)여야 하며, 그 디렉터리에 대한 실행 권한(`x`)이 있어야 지나갈 수 있다(7주차).
4. 경로 끝의 `/`는 마지막 이름이 디렉터리여야 한다는 뜻이다. `ls file.txt/`는 `file.txt`가 일반 파일이면 `Not a directory` 오류를 낸다.

예를 들어 `/usr/./lib/../bin//ls`는 `/` → `usr` → `.`(그대로 `/usr`) → `lib`(`/usr/lib`) → `..`(`/usr`) → `bin`(`/usr/bin`, 이어진 `/`는 하나로 봄) → `ls` 순으로 해석되어 `/usr/bin/ls`가 된다. `realpath` 명령은 이렇게 해석한 결과를 `.`, `..`, 심볼릭 링크가 없는 절대 경로로 출력한다.

```text
$ realpath /usr/./lib/../bin//ls
/usr/bin/ls
$ cd /usr/lib
$ realpath ../../etc/hostname
/etc/hostname
```

`~`(물결표)는 경로 해석 규칙에 들어 있지 않다. `~`를 홈 디렉터리로 바꾸는 것은 커널이 아니라 셸이며(6주차), 셸은 단어의 맨 앞에 있고 따옴표로 감싸지 않은 `~`만 바꾼다. 따라서 `cd "~"`는 홈 디렉터리가 아니라 현재 디렉터리 안의 `~`라는 이름의 디렉터리로 가려 하고, `a~b`의 `~`는 그대로 남는다.

### 3.5 심볼릭 링크가 낀 경로와 논리 경로, 물리 경로

Ubuntu에서 `/bin`은 `usr/bin`을 가리키는 심볼릭 링크이다(2.1절). 심볼릭 링크를 지나서 들어간 디렉터리에서는 "지나온 경로"와 "실제 위치"가 다르다.

- **논리 경로(logical path):** 사용자가 지나온 이름을 그대로 이은 경로이다. Bash의 `cd`와 `pwd`는 기본적으로 논리 경로를 쓴다(`-L`).
- **물리 경로(physical path):** 심볼릭 링크를 모두 따라가 실제 디렉터리로 바꾼 경로이다. `pwd -P`와 `cd -P`가 물리 경로를 쓰며, 커널의 경로 해석은 언제나 물리 경로를 따른다.

```text
$ cd /bin
$ pwd
/bin
$ pwd -P
/usr/bin
$ ls /bin/.. | head -3
bin
games
include
$ cd ..
$ pwd
/
```

`ls /bin/..`은 커널이 `/bin`을 `/usr/bin`으로 따라간 뒤 그 부모로 가므로 `/usr`의 내용(`bin`, `games`, `include`, ...)을 출력한다. 반면 Bash의 `cd ..`은 논리 경로 `/bin`에서 마지막 이름을 지워 `/`로 간다. 같은 `..`이라도 커널이 해석하는지 셸이 해석하는지에 따라 결과가 다르다.

> **주의:** 스크립트에서 `cd`로 옮겨 간 뒤 상대 경로 `..`을 다른 명령의 인자로 쓰면, `cd ..`과 `ls ..`이 서로 다른 디렉터리를 가리킬 수 있다. 실제 위치가 중요하면 `cd -P`를 쓰거나 `realpath`로 경로를 먼저 확정한다.

## 4. 파일 및 디렉터리 이름 규칙

### 4.1 규칙

- 이름에 `/`를 사용할 수 없다. `/`는 경로의 구분자이기 때문이다.
- 문자, 숫자, 하이픈(`-`), 밑줄(`_`), 마침표(`.`)를 사용할 수 있다.
- `/`를 제외한 특수 문자도 쓸 수 있지만, `>`, `|`, `:`, `&`, 공백 문자는 피하는 것이 좋다.
- **대소문자 구분:** `File.txt`와 `file.txt`는 서로 다른 파일이다.
- `.`으로 시작하는 이름은 숨김 파일로 간주된다.
- 널 문자(`\0`)는 사용할 수 없다.
- 파일 이름의 최대 길이는 일반적으로 255바이트이다(ext4 기준). UTF-8에서 한글은 한 글자가 3바이트이므로 한글 이름은 더 짧아진다.

### 4.2 예시

| 좋은 이름 | 나쁜 이름 | 잘못된 이름 |
|-----------|-----------|-------------|
| `game.txt` | `&game` | `myhome/` |
| `hello.c` | `*dir` | `/test` |
| `test` | `my home` | `bad/name` |
| `sample11` | `game\` | |

*표 6. 좋은 이름, 나쁜 이름, 사용할 수 없는 이름의 예*

### 4.3 공백과 특수 문자가 든 이름 다루기

셸은 명령줄을 공백에서 끊어 인자로 나누고, `*`, `?`, `&`, `>`, `|`, `;` 같은 문자를 특별하게 해석한다(6주차). 그래서 표 6의 나쁜 이름도 파일 시스템에는 만들어질 수 있지만, 명령줄에서 다룰 때마다 셸이 그 이름을 다르게 해석하지 않도록 막아야 한다.

```text
$ touch 'my home'
$ ls my home
ls: cannot access 'my': No such file or directory
ls: cannot access 'home': No such file or directory
$ ls 'my home'
'my home'
$ ls my\ home
'my home'
```

- `ls my home`은 셸이 공백에서 끊어 `my`와 `home` 두 인자로 넘기므로 두 파일을 찾다가 실패한다. 이름 전체를 작은따옴표로 감싸거나 공백 앞에 `\`를 붙이면 하나의 인자가 된다.
- GNU `ls`는 출력이 터미널이면 공백 같은 특수 문자가 든 이름을 셸에 그대로 다시 입력할 수 있는 형태(`'my home'`)로 감싸 출력하고, 출력이 파이프나 파일이면 이름을 감싸지 않는다. 따옴표는 이름의 일부가 아니다.

이름이 `-`로 시작하면 셸이 아니라 명령이 그 이름을 옵션으로 해석한다.

```text
$ touch -- -file
$ rm -file
rm: invalid option -- 'l'
Try 'rm ./-file' to remove the file '-file'.
Try 'rm --help' for more information.
$ rm -- -file
```

`rm -file`은 `-f`, `-i`, `-l`, `-e`라는 네 개의 옵션 묶음으로 해석되고, `rm`에 `-l` 옵션이 없으므로 오류가 난다. 명령 대부분은 `--`를 "옵션의 끝"으로 보아 그 뒤의 인자를 모두 이름으로 다루므로 `rm -- -file`로 지울 수 있다. 오류 메시지가 알려 주듯 `./-file`처럼 경로를 붙여 `-`로 시작하지 않게 하는 방법도 있다. `touch -- -file`의 `--`도 같은 이유로 필요하다.

## 5. 디렉터리 명령어

### 5.1 pwd: 현재 작업 디렉터리 출력

`pwd`(print working directory)는 현재 디렉터리의 절대 경로를 출력한다.

```bash
$ pwd
/home/user1
```

### 5.2 cd: 디렉터리 변경

```bash
cd /tmp                 # 절대 경로
cd ../usr/lib           # 상대 경로
cd ~                    # 홈 디렉터리
cd                      # 홈 디렉터리 (단축키)
cd -                    # 이전 디렉터리
cd ..                   # 상위 디렉터리
```

위의 `cd ../usr/lib`는 현재 디렉터리가 `/tmp`일 때 상위 디렉터리인 `/`를 거쳐 `/usr/lib`로 이동한다.

### 5.3 ls: 디렉터리 내용 목록

```bash
ls                      # 현재 디렉터리 목록
ls -a                   # 숨김 파일 표시 (.으로 시작하는 파일)
ls -l                   # 상세 형식 (자세한 정보)
ls -la                  # 상세 형식 + 숨김 파일
ls -lh                  # 사람이 읽기 쉬운 파일 크기
ls -R                   # 재귀적 목록
ls -F                   # 유형 표시자 추가 (*=실행 파일, /=디렉터리, @=링크)
ls -i                   # inode 번호 표시
ls -d                   # 내용이 아닌 디렉터리 자체 표시
ls -t                   # 수정 시간순 정렬
ls -S                   # 파일 크기순 정렬
```

이 밖에 `-A`는 `.`과 `..`을 제외한 모든 파일을, `-L`은 심볼릭 링크의 경우 원본 파일의 정보를 출력한다. `ls /tmp`처럼 디렉터리 이름을 인자로 주면 그 디렉터리의 내용을 출력하고, `ls .bashrc`처럼 파일 이름을 주면 파일이 있는지 확인할 수 있다(없으면 `ls: cannot access 'game': No such file or directory` 같은 오류가 출력된다). `ls -ld /`처럼 여러 옵션을 한꺼번에 쓸 수도 있다.

**`ls -l` 출력 이해:**

```text
drwxr-xr-x  2  user1  user1  4096  Mar 21 12:05  Documents
│└─┬──┘└┬─┘ │   │       │      │       │            │
│  │    │   │   │       │      │       │            └── 파일 이름
│  │    │   │   │       │      │       └── 최종 수정일
│  │    │   │   │       │      └── 크기 (바이트)
│  │    │   │   │       └── 그룹 소유자
│  │    │   │   └── 파일 소유자
│  │    │   └── 하드 링크 수
│  │    └── 기타 사용자 권한 (r-x)
│  └── 그룹 권한 (r-x)
│       소유자 권한 (rwx)
└── 파일 유형 (d=디렉터리, -=파일, l=링크)
```

*그림 3. ls -l 출력의 필드 구성*

### 5.4 mkdir: 디렉터리 생성

```bash
mkdir mydir                     # 단일 디렉터리 생성
mkdir -p parent/child/grandchild  # 중첩 디렉터리 생성
mkdir dir1 dir2 dir3            # 여러 디렉터리 생성
```

`-p` 없이 `mkdir temp/mid/han`처럼 중간 디렉터리가 없는 경로를 주면 `No such file or directory` 오류가 난다. `-p`를 쓰면 없는 중간 디렉터리를 자동으로 만든 뒤 지정한 디렉터리를 만든다.

### 5.5 rmdir: 빈 디렉터리 제거

```bash
rmdir mydir                     # 빈 디렉터리만 제거
rmdir -p parent/child/grandchild  # 중첩된 빈 디렉터리 제거
```

`rmdir -p`는 지정한 디렉터리를 지운 뒤, 그 부모 디렉터리가 빈 디렉터리가 되면 부모 디렉터리도 차례로 지운다. 비어 있지 않은 디렉터리는 `rmdir`로 지울 수 없으며(`rmdir: failed to remove 'temp': Directory not empty`), 이때는 4주차에서 다루는 `rm -r`을 쓴다.

### 5.6 유사 명령어: dir, vdir

```bash
dir                 # ls와 유사 (기본 색상 없음)
vdir                # ls -l과 유사
```

### 5.7 ls -l 출력의 세부 규칙

그림 3의 필드에는 처음 보면 헷갈리는 규칙이 몇 가지 있다. 다음은 GNU `ls`(Ubuntu 24.04의 coreutils)의 규칙이다.

- **시간의 표시.** `ls -l`은 기본적으로 최종 수정 시간(mtime)을 출력한다. 시간이 현재로부터 6개월이 지나지 않았으면 `Mar 21 12:05`처럼 월, 일, 시각을, 6개월이 지났거나 미래의 시간이면 `Mar 21  2024`처럼 월, 일, 연도를 출력한다. 따라서 같은 목록 안에서 어떤 줄은 시각을, 어떤 줄은 연도를 보여 줄 수 있다. `--time-style=long-iso`를 주면 언제나 `2025-03-21 12:05` 형식으로 출력한다.
- **`total` 줄.** `ls -l`의 첫 줄 `total N`은 목록에 나온 파일들이 디스크에서 차지하는 블록 수의 합이며, 기본 단위는 1024바이트이다. 1.4절의 `ls -la d1`에서는 디렉터리 다섯 개(`.`, `..`, `a`, `b`, `c`)가 4 KiB씩, 빈 파일 `f`가 0을 차지하므로 `total 20`이다. 이 값은 파일 크기의 합이 아니다.
- **크기의 단위.** `-h`는 크기를 1024의 거듭제곱 단위(`K`, `M`, `G`)로 줄여 보여 주고, `--si`는 1000의 거듭제곱 단위로 보여 준다 [4]. 1,550,000바이트는 `-h`로 `1.5M`(1,550,000 ÷ 1,048,576 ≈ 1.48을 올림), `--si`로 `1.6M`(1.55를 올림)이다. 두 옵션 모두 소수 첫째 자리로 올림하여 표시한다.
- **정렬.** 기본은 이름순이며, 순서는 로케일을 따른다. 한국어나 영어 UTF-8 로케일에서는 대소문자를 거의 구분하지 않는 사전식 순서이고, `LC_ALL=C ls`처럼 C 로케일에서는 바이트 값의 순서라서 대문자로 시작하는 이름이 모두 소문자 이름보다 앞에 온다. `-t`는 수정 시간이 최근인 것부터, `-S`는 큰 것부터 정렬하며, `-r`은 순서를 뒤집는다.
- **디렉터리 인자.** `ls -l dir`은 `dir` 안의 파일 목록을, `ls -ld dir`은 `dir` 자신의 정보를 출력한다. 디렉터리의 권한이나 소유자를 확인하려면 `-d`가 필요하다.

```text
$ ls -l --time-style=long-iso /etc/hostname
-rw-r--r-- 1 root root 9 2025-03-11 14:20 /etc/hostname
$ ls -ld /tmp
drwxrwxrwt 18 root root 4096 Mar 21 12:30 /tmp
```

`/etc/hostname`의 크기 9바이트는 컴퓨터 이름 `myubuntu`의 8글자와 줄바꿈 문자 하나를 합친 값이다. `/tmp`의 권한 끝의 `t`는 7주차의 Sticky Bit이다.

### 5.8 cd, mkdir, rmdir의 세부 동작

- **`cd`.** 인자 없는 `cd`는 환경 변수 `HOME`이 가리키는 디렉터리로 간다. `cd -`는 환경 변수 `OLDPWD`에 저장된 직전 디렉터리로 가면서 그 경로를 출력한다. `cd`는 셸 내장 명령이다. 새 프로그램으로 실행되면 그 프로그램의 작업 디렉터리만 바뀌고 셸의 작업 디렉터리는 그대로이므로, 작업 디렉터리를 바꾸는 명령은 셸 안에서 실행되어야 한다(6주차).
- **`mkdir`.** `-p`는 중간 디렉터리를 만들 뿐 아니라, 만들려는 디렉터리가 이미 있어도 오류를 내지 않는다. 그래서 스크립트에서 "없으면 만든다"는 뜻으로 `mkdir -p`를 쓴다. `-v`는 만든 디렉터리를 하나씩 출력하고, `-m 700`처럼 `-m`으로 권한을 지정할 수 있다(7주차).
- **`rmdir`.** 비어 있지 않은 디렉터리는 지우지 않는다. `rmdir -p`가 부모를 차례로 지우다가 비어 있지 않은 부모를 만나면 오류를 낸다.

```text
$ mkdir temp/mid/han
mkdir: cannot create directory 'temp/mid/han': No such file or directory
$ mkdir -pv temp/mid/han
mkdir: created directory 'temp'
mkdir: created directory 'temp/mid'
mkdir: created directory 'temp/mid/han'
$ mkdir -p temp/mid/han
$ rmdir temp
rmdir: failed to remove 'temp': Directory not empty
$ rmdir -p temp/mid/han
$ ls -d temp
ls: cannot access 'temp': No such file or directory
```

두 번째 `mkdir -p temp/mid/han`은 디렉터리가 이미 있으므로 아무 일도 하지 않고 조용히 끝난다. `rmdir -p temp/mid/han`은 `han`, `mid`, `temp`를 차례로 지운다.

## 6. 파일 내용 명령어

### 6.1 cat: 연결 및 표시

```bash
cat file.txt                    # 전체 파일 표시
cat -n file.txt                 # 줄 번호 표시
cat file1.txt file2.txt         # 여러 파일 연결
cat > newfile.txt               # stdin에서 파일 생성 (Ctrl+D로 종료)
cat >> existingfile.txt         # stdin에서 파일에 추가
```

### 6.2 more와 less: 파일 페이지 넘기기

```bash
more file.txt                   # 주로 앞으로 페이지 넘기기
less file.txt                   # 앞뒤로 페이지 넘기기 (권장)
```

`more`는 내용을 화면 단위로 출력하며, `Space`를 누르면 다음 화면을, `Enter`를 누르면 한 줄씩 스크롤하고, `more +20 file.txt`처럼 출력을 시작할 줄 번호를 지정할 수도 있다. 파일을 볼 때는 `b`로 한 화면 뒤로 갈 수 있지만, 파이프로 받은 입력은 뒤로 넘길 수 없다. `less` 안에서는 다음 키로 이동하고 검색한다.

| 키 | 동작 |
|----|------|
| `Space` / `f` / `Ctrl + F` | 다음 페이지 |
| `b` / `Ctrl + B` | 이전 페이지 |
| `j` / `↓` | 한 줄 아래로 스크롤 |
| `k` / `↑` | 한 줄 위로 스크롤 |
| `g` | 처음으로 이동 |
| `G` | 끝으로 이동 |
| `/pattern` | 앞으로 검색 |
| `?pattern` | 뒤로 검색 |
| `n` | 다음 검색 결과 |
| `q` | 종료 |

*표 7. less의 탐색 키*

### 6.3 head와 tail: 파일 부분 보기

```bash
head file.txt                   # 처음 10줄 (기본값)
head -n 20 file.txt             # 처음 20줄
head -n -5 file.txt             # 마지막 5줄을 제외한 모든 줄

tail file.txt                   # 마지막 10줄 (기본값)
tail -n 20 file.txt             # 마지막 20줄
tail -f /var/log/syslog         # 실시간으로 로그 추적
```

`head`와 `tail`은 `-n 20` 대신 `-20`처럼 숫자만 옵션으로 줄 수도 있다. `tail -n +20 file.txt`처럼 줄 수 앞에 `+`를 붙이면 20번째 줄부터 끝까지 출력한다. `tail -f`는 출력을 끝내지 않고 파일에 새로 추가되는 내용을 계속 출력하며, `Ctrl + C`로 멈춘다.

> **핵심:** `tail -f`는 로그 파일에 어떤 내용이 실시간으로 추가되는지 모니터링할 때 유용하다.

### 6.4 cat, head, tail의 세부 옵션

`cat`의 옵션은 눈에 보이지 않는 문자를 확인할 때 유용하다. 탭 문자와 줄 끝의 공백, 연속된 빈 줄이 든 파일 `t.txt`에 적용하면 다음과 같다.

```text
$ cat -A t.txt
name^Iscore $
$
kim^I90$
$
$
lee^I85$
$ cat -n t.txt
     1	name	score
     2
     3	kim	90
     4
     5
     6	lee	85
$ cat -b t.txt
     1	name	score

     2	kim	90


     3	lee	85
$ cat -s t.txt
name	score

kim	90

lee	85
```

- `-A`는 탭을 `^I`로, 줄 끝을 `$`로 보여 주고 그 밖의 제어 문자도 `^` 표기로 바꾼다. 첫 줄의 `score $`에서 `$` 앞의 공백이 줄 끝에 남은 공백이다. 셸 스크립트나 설정 파일이 보이지 않는 문자 때문에 동작하지 않을 때 원인을 찾는 데 쓴다.
- `-n`은 모든 줄에, `-b`는 빈 줄이 아닌 줄에만 번호를 붙인다.
- `-s`는 이어진 빈 줄을 하나로 줄인다. 4번과 5번의 두 빈 줄이 하나가 되었다.

`head`와 `tail`은 줄 대신 바이트를 셀 수도 있다. `head -c 100`은 처음 100바이트를, `tail -c 100`은 마지막 100바이트를 출력한다. `head -n -5`처럼 음수를 주면 "마지막 5줄을 뺀 나머지", `tail -n +5`처럼 `+`를 붙이면 "5번째 줄부터 끝까지"이므로, 두 명령을 이어 파일의 특정 줄 범위를 뽑을 수 있다.

```text
$ head -n 7 /etc/passwd | tail -n +5
sync:x:4:65534:sync:/bin:/bin/sync
games:x:5:60:games:/usr/games:/usr/sbin/nologin
man:x:6:12:man:/var/cache/man:/usr/sbin/nologin
```

처음 7줄 가운데 5번째 줄부터 출력하므로 5\~7번째 줄이 나온다. 일반적으로 m번째 줄부터 n번째 줄까지는 `head -n n | tail -n +m`으로 뽑는다.

`tail -f`는 파일의 이름이 아니라 처음 연 파일 자체를 따라간다. 로그 순환(log rotation) 프로그램이 로그 파일의 이름을 바꾸고 같은 이름의 새 파일을 만들면, `tail -f`는 이름이 바뀐 옛 파일을 계속 지켜보아 새 로그를 보여 주지 않는다. `tail -F`는 `--follow=name --retry`와 같아서, 파일이 지워지거나 바뀌면 같은 이름의 파일을 다시 열어 계속 따라간다 [5]. 오래 지켜볼 로그에는 `tail -F`가 알맞다.

> **주의:** 실행 파일 같은 이진 파일을 `cat`으로 출력하면 그 안의 바이트가 터미널의 제어 문자로 해석되어 화면의 글자가 깨지거나 입력이 이상하게 보일 수 있다. 이때는 `reset` 명령으로 터미널을 초기화한다. 파일의 종류를 모르면 먼저 `file`로 확인하고, 이진 파일의 내용은 `less`나 `od`로 본다.

## 7. 모범 사례

### 7.1 탐색 팁

- `Tab` 자동 완성을 사용하여 경로의 오타를 방지한다.
- `cd -`를 사용하여 두 디렉터리 사이를 오간다.
- `pushd`와 `popd`로 디렉터리 스택을 관리하며 이동할 수 있다.
- 스크립트에서는 현재 디렉터리에 영향을 받지 않도록 절대 경로를 쓰는 것이 안전하다.

### 7.2 흔한 실수

| 실수 | 올바른 방법 |
|------|------------|
| 파일 이름에 공백 사용 | 밑줄이나 하이픈 사용 |
| 대소문자 구분 잊기 | Linux는 대소문자를 구분함 |
| `/root`와 `/` 혼동 | `/root`는 root의 홈이고, `/`는 파일 시스템의 루트 |
| `rm -rf /` 사용 | 절대 실행하지 않음. 시스템 전체가 삭제될 수 있으며, GNU `rm`은 기본적으로 `/` 자체의 재귀 삭제를 거부하지만(`--preserve-root`) `rm -rf /*`는 막지 못함 |
| 이름이 `-`로 시작하는 파일을 `rm -file`로 지우기 | `rm -- -file` 또는 `rm ./-file` |
| 공백이 든 이름을 따옴표 없이 쓰기 | `'my home'` 또는 `my\ home` |
| `cd "~"`로 홈 디렉터리에 가려 하기 | 따옴표 없이 `cd ~` 또는 인자 없이 `cd` |
| `ls -l dir`로 디렉터리 자신의 권한 확인 | `ls -ld dir` |
| 재부팅 뒤에도 필요한 파일을 `/tmp`에 두기 | `/var/tmp`나 홈 디렉터리에 둠 |

## 개념 적용

**T/F 점검:**

| 문장 | 판단과 근거 |
|:-----|:-----|
| 파일의 이름은 그 파일의 inode에 저장된다. | **F.** 이름은 파일을 담은 디렉터리의 표에 "이름과 inode 번호"의 쌍으로 저장된다. |
| 하위 디렉터리가 4개이고 일반 파일이 10개인 디렉터리의 링크 수는 ext4에서 6이다. | **T.** 링크 수는 2 + 하위 디렉터리 수이며, 일반 파일은 영향을 주지 않는다. |
| `/../../etc`는 존재하지 않는 경로이므로 오류가 난다. | **F.** 루트의 `..`은 루트 자신이므로 이 경로는 `/etc`이다. |
| Ubuntu에서 `cd /bin; cd ..` 뒤의 `pwd`는 `/usr`를 출력한다. | **F.** Bash의 `cd`는 논리 경로를 쓰므로 `/bin`에서 `..`은 `/`이다. `ls /bin/..`이라면 `/usr`의 내용이 나온다. |
| `ls -l`에서 장치 파일의 크기 자리에 나오는 `8, 1`은 8.1 KB를 뜻한다. | **F.** 장치 파일에는 크기 대신 주 번호 8과 부 번호 1이 나온다. |
| `total 20`은 목록에 나온 파일 크기의 합이 20바이트라는 뜻이다. | **F.** 파일들이 차지하는 디스크 블록의 합을 1024바이트 단위로 나타낸 값이다. |
| `tail -F`는 로그 파일이 순환되어 같은 이름의 새 파일이 생겨도 새 파일을 따라간다. | **T.** `-F`는 `--follow=name --retry`이므로 이름으로 파일을 다시 연다. |

| 디렉터리의 실체 | 디렉터리는 이름과 inode 번호의 표이며, ext4에서 링크 수는 2 + 하위 디렉터리 수이다. |
| 장치 파일 | 데이터 대신 드라이버를 가리키는 주 번호와 부 번호를 가지며, 블록 장치(`b`)와 문자 장치(`c`)로 나뉜다. |
| FHS | 공유 가능 여부와 정적, 가변 여부로 디렉터리의 용도를 정한 표준이며, `/usr`는 공유 가능한 정적 자료, `/var`는 가변 자료를 담는다. |
| 경로 해석 | 루트나 현재 디렉터리에서 출발해 이름을 하나씩 찾으며, 이어진 `/`는 하나로, 루트의 `..`은 루트로 본다. |
| 논리 경로와 물리 경로 | Bash의 `cd`와 `pwd`는 지나온 이름의 논리 경로를, 커널과 `pwd -P`는 심볼릭 링크를 따라간 물리 경로를 쓴다. |
| 특수한 이름 | 공백이 든 이름은 따옴표나 `\`로, `-`로 시작하는 이름은 `--`나 `./`로 다룬다. |
| `ls -l`의 시간과 `total` | 6개월이 지난 시간은 연도로 표시하고, `total`은 1024바이트 단위의 블록 합이다. |

## 점검 문제

1. **상대 경로 작성:** 현재 디렉터리가 `/usr/lib`일 때 `/usr/bin/ls`와 `/etc/hostname`을 각각 상대 경로로 쓰라.

   <details>
   <summary>정답</summary>

   `/usr/bin/ls`는 `..`으로 `/usr`에 올라간 뒤 `bin/ls`로 내려가므로 `../bin/ls`이다. `/etc/hostname`은 `..`을 두 번 써서 `/`까지 올라간 뒤 `etc/hostname`으로 내려가므로 `../../etc/hostname`이다.

   </details>

2. **유형 표시자:** Ubuntu에서 `ls -F /`의 출력에 `bin@`, `boot/`가 나타났다. `@`와 `/`는 각각 무엇을 뜻하며, 실행 파일에는 어떤 표시가 붙는가?

   <details>
   <summary>정답</summary>

   `@`는 심볼릭 링크라는 뜻으로, `/bin`이 `/usr/bin`을 가리키는 심볼릭 링크임을 보여 준다. `/`는 디렉터리라는 뜻이다. 실행 파일에는 이름 뒤에 `*`가 붙는다.

   </details>

3. **rmdir의 동작:** 빈 디렉터리 `a/b/c`가 있고 `a`와 `b`에는 다른 내용이 없다. `rmdir -p a/b/c`를 실행하면 어떻게 되는가? 또 `c` 안에 파일이 하나 있으면 어떻게 되는가?

   <details>
   <summary>정답</summary>

   먼저 `a/b/c`가 지워지고, 그러면 `b`가 빈 디렉터리가 되므로 `a/b`가 지워지며, 이어서 `a`도 지워진다. `c` 안에 파일이 있으면 `c`가 빈 디렉터리가 아니므로 `Directory not empty` 오류와 함께 아무것도 지워지지 않는다.

   </details>

4. **less 탐색:** `less /etc/services`로 파일을 연 상태에서 문자열 `TCP`가 있는 곳을 찾고, 다음 검색 결과로 이동한 뒤, `less`를 끝내는 키 입력을 순서대로 쓰라.

   <details>
   <summary>정답</summary>

   `/TCP`를 입력하고 `Enter`를 눌러 앞으로 검색한다. `n`을 눌러 다음 검색 결과로 이동한다. `q`를 눌러 `less`를 끝낸다.

   </details>

5. **디렉터리 링크 수:** 빈 디렉터리 `p` 안에서 `mkdir a b; mkdir a/x; touch f1 f2`를 실행했다. `p`, `a`, `b`, `a/x`의 링크 수를 각각 구하라(ext4).

   <details>
   <summary>정답</summary>

   링크 수는 2 + 바로 아래 하위 디렉터리 수이다. `p`는 하위 디렉터리 `a`, `b`를 가지므로 4, `a`는 `x` 하나를 가지므로 3, `b`와 `a/x`는 하위 디렉터리가 없으므로 2이다. 일반 파일 `f1`, `f2`는 링크 수에 영향을 주지 않는다.

   </details>

6. **경로 해석:** 현재 디렉터리가 `/home/user1`일 때 다음 경로가 가리키는 절대 경로를 쓰라. (가) `./../user2//docs/.` (나) `/../../tmp/../etc` (다) `../../../..`

   <details>
   <summary>정답</summary>

   (가) `.`은 `/home/user1`, `..`은 `/home`, 이어서 `user2`, `docs`로 내려가고 끝의 `.`은 그대로이므로 `/home/user2/docs`이다. (나) 루트의 `..`은 루트이므로 `/tmp/../etc`가 되고, `tmp`에서 `..`으로 올라가 `/etc`이다. (다) `/home/user1`에서 두 번 올라가면 `/`이고, 그 뒤의 `..`은 계속 `/`이므로 `/`이다.

   </details>

7. **논리 경로와 물리 경로:** Ubuntu에서 `cd /bin` 다음에 `pwd`, `pwd -P`, `ls ..`을 차례로 실행했다. 각 출력을 설명하라.

   <details>
   <summary>정답</summary>

   `pwd`는 Bash가 기억하는 논리 경로 `/bin`을, `pwd -P`는 심볼릭 링크를 따라간 물리 경로 `/usr/bin`을 출력한다. `ls ..`의 `..`은 커널이 물리 경로에서 해석하므로 `/usr/bin`의 부모인 `/usr`의 내용이 나온다.

   </details>

8. **장치 파일:** `ls -l /dev/sdb2`의 출력이 `brw-rw---- 1 root disk 8, 18 ...`이다. 첫 글자 `b`와 `8, 18`의 뜻을 쓰고, 일반 사용자 user1이 이 장치를 직접 읽을 수 있는지 판단하라.

   <details>
   <summary>정답</summary>

   `b`는 블록 장치라는 뜻이고, `8, 18`은 주 번호 8(SCSI, SATA 디스크 드라이버)과 부 번호 18이다. 권한이 `rw-rw----`이고 소유자가 root, 그룹이 `disk`이므로, `disk` 그룹에 속하지 않은 user1은 읽을 수 없다.

   </details>

9. **특수한 이름:** 현재 디렉터리에 `-r`이라는 이름의 파일과 `docs`라는 디렉터리가 있다. 사용자가 `rm *`를 실행하면 어떤 일이 생길 수 있는지 설명하고, `-r` 파일만 안전하게 지우는 명령을 쓰라.

   <details>
   <summary>정답</summary>

   셸이 `*`를 펼친 인자 목록에 `-r`이 들어가고, GNU `rm`은 인자의 위치와 관계없이 `-`로 시작하는 인자를 옵션으로 해석하므로 `rm -r docs`와 같은 명령이 된다. 그래서 `-r`이 파일 이름이 아니라 재귀 삭제 옵션으로 해석되고, 디렉터리 `docs`가 그 내용과 함께 지워진다. 이름이 `-`로 시작하는 파일만 지우려면 `rm -- -r` 또는 `rm ./-r`을 쓴다.

   </details>

10. **줄 범위 추출:** 파일 `data.txt`의 12번째 줄부터 15번째 줄까지만 출력하는 명령을 `head`와 `tail`로 쓰라.

    <details>
    <summary>정답</summary>

    `head -n 15 data.txt | tail -n +12`이다. `head -n 15`가 처음 15줄을 넘기고, `tail -n +12`가 그중 12번째 줄부터 끝까지 출력하므로 12\~15번째 줄의 네 줄이 나온다.

    </details>
