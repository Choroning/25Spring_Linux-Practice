## 1. 프로세스 이해

### 1.1 프로세스란?

**프로세스(Process)** 는 실행 중인 프로그램의 인스턴스이다. Linux는 동시에 여러 프로세스를 실행하는 다중 프로세스 시스템이다. 각 프로세스는 다음을 가진다:
- **PID (Process ID):** 각 프로세스를 구별하는 고유 번호이다.
- **PPID (Parent Process ID):** 해당 프로세스를 생성한 부모 프로세스의 PID이다.
- **UID/GID:** 프로세스를 실행한 사용자와 그룹이다.
- **상태(State):** 실행 중, 대기 중, 정지, 좀비 등의 상태이다.
- **우선순위(Priority):** CPU 스케줄링에 쓰는 우선순위 값이다.

Linux의 모든 프로세스는 부모-자식 관계를 가진다. 부모 프로세스가 자식 프로세스를 생성하며, 예를 들어 셸에서 명령을 실행하면 셸이 부모, 명령이 자식 프로세스가 된다. 부팅할 때 커널이 처음 실행하는 1번 프로세스는 `systemd`(`/sbin/init`)이고, 2번 프로세스는 커널 스레드를 관리하는 `kthreadd`이다. 다른 모든 프로세스는 이 두 프로세스의 자손이다.

### 1.2 프로세스 유형

| 유형 | 설명 | 예시 |
|------|-------------|---------|
| **포그라운드** | 대화형, 터미널에 연결됨 | `vi file.txt` |
| **백그라운드** | 터미널과 독립적으로 실행 | `command &` |
| **데몬** | 백그라운드에서 실행되는 시스템 서비스 | `sshd`, `cron`, `nginx` |
| **좀비** | 완료되었지만 부모가 아직 정리하지 않은 상태 | defunct 프로세스 |
| **고아** | 부모가 종료되어 init/systemd에 의해 입양됨 | |

*표 1. 프로세스의 유형*

- **데몬 프로세스**는 특정 서비스를 제공하기 위해 존재하며, 보통 부팅할 때 `systemd`가 시작하여 터미널과 관계없이 계속 실행된다.
- **고아 프로세스**는 자식 프로세스가 아직 실행 중인데 부모 프로세스가 먼저 종료된 경우의 자식 프로세스이다. 고아 프로세스는 1번 프로세스(또는 지정된 다른 프로세스)가 새 부모로 입양한다.
- **좀비 프로세스**는 실행을 마쳤는데도 부모가 종료 상태를 수집하지 않아 프로세스 테이블에 남아 있는 자식 프로세스이다. 프로세스 목록에 `defunct`로 표시되기도 한다. 좀비 프로세스는 CPU나 메모리를 거의 쓰지 않지만 프로세스 테이블의 항목을 차지하므로, 많이 쌓이면 테이블이 부족해져 정상적인 프로세스를 실행하지 못할 수 있다.

### 1.3 프로세스 상태

| 상태 | 기호 | 설명 |
|-------|--------|-------------|
| 실행 중 | `R` | 현재 CPU에서 실행 중 |
| 대기 중 | `S` | 이벤트를 기다리는 중 (인터럽트 가능) |
| 비인터럽트 대기 | `D` | I/O를 기다리는 중 (인터럽트 불가) |
| 정지 | `T` | 일시 중지됨 (예: Ctrl+Z) |
| 좀비 | `Z` | 종료되었으나 부모가 종료 상태를 수집하지 않음 |

*표 2. 프로세스 상태 기호*

`ps aux`의 STAT 열에는 `Ss`, `S+`, `I<`처럼 상태 기호 뒤에 문자가 더 붙기도 한다. `s`는 세션 리더, `+`는 포그라운드 프로세스 그룹, `<`는 높은 우선순위를 뜻하며, `I`는 유휴 상태의 커널 스레드를 뜻한다.

## 2. 프로세스 확인

### 2.1 ps: 프로세스 상태

`ps` 명령은 현재 실행 중인 프로세스의 정보를 출력하며, 형식은 `ps [옵션]`이다. `ps`의 옵션은 세 가지 유형이 있다.

- **유닉스(SVR4) 옵션:** 묶어서 쓸 수 있고 `-`로 시작한다 (예: `-ef`).
- **BSD 옵션:** 묶어서 쓸 수 있고 `-`로 시작하지 않는다 (예: `aux`).
- **GNU 옵션:** `--` 두 개로 시작한다 (예: `--pid`).

```bash
ps                      # 현재 터미널의 현재 사용자 프로세스
ps -e                   # 모든 프로세스
ps -f                   # 전체 형식
ps -ef                  # 모든 프로세스, 전체 형식
ps aux                  # BSD 스타일 전체 프로세스 상세 정보
ps -u username          # 특정 사용자의 프로세스
ps -p PID               # PID로 특정 프로세스 조회
ps --forest             # 트리 형태로 프로세스 보기
```

| 옵션 | 유형 | 기능 |
|------|------|------|
| `-e` | 유닉스 | 시스템에서 실행 중인 모든 프로세스의 정보를 출력한다. |
| `-f` | 유닉스 | 프로세스의 자세한 정보(PPID, C, STIME 등)를 출력한다. |
| `-u uid` | 유닉스 | 특정 사용자의 모든 프로세스 정보를 출력한다. |
| `-p pid` | 유닉스 | PID로 지정한 특정 프로세스의 정보를 출력한다. |
| `a` | BSD | 터미널에서 실행한 프로세스의 정보를 출력한다. |
| `u` | BSD | 프로세스 소유자 이름, CPU 사용량, 메모리 사용량 등 상세 정보를 출력한다. |
| `x` | BSD | 터미널과 관계없이 시스템에서 실행 중인 모든 프로세스의 정보를 출력한다. |
| `--pid PID 목록` | GNU | 목록으로 지정한 특정 PID의 정보를 출력한다. |

*표 3. ps의 주요 옵션*

옵션 없이 `ps`를 실행하면 현재 셸이나 터미널에서 실행한 사용자 프로세스의 PID, TTY, TIME, CMD만 출력한다. `-f` 옵션을 붙이면 다음처럼 PPID와 C(CPU 사용량), 시작 시간 등의 정보가 추가로 출력된다.

```text
$ ps -f
UID          PID    PPID  C STIME TTY          TIME CMD
user1       1584    1583  0 00:00 pts/0    00:00:00 -bash
user1       1660    1584  0 00:16 pts/0    00:00:00 ps -f
```

| 항목 | 의미 | 항목 | 의미 |
|------|------|------|------|
| UID | 프로세스를 실행한 사용자 ID | STIME | 프로세스의 시작 날짜나 시간 |
| PID | 프로세스 번호 | TTY | 프로세스가 실행된 터미널의 종류와 번호 |
| PPID | 부모 프로세스 번호 | TIME | 프로세스 실행 시간 |
| C | CPU 사용량 (% 값) | CMD | 실행되고 있는 프로그램 이름 (명령) |

*표 4. `ps -f`의 출력 정보*

위 출력에서 `ps -f`의 PPID 1584는 `-bash`의 PID와 같으므로, `ps -f`가 셸의 자식 프로세스임을 알 수 있다.

**`ps aux` 출력 이해:**

```text
USER  PID  %CPU  %MEM  VSZ    RSS   TTY  STAT  START  TIME  COMMAND
root    1   0.0   0.3  168K  12K    ?    Ss    10:00  0:01  /sbin/init
```

| 항목 | 의미 |
|------|------|
| USER | 사용자 계정 이름 |
| %CPU | 퍼센트로 표시한 CPU 사용량 |
| %MEM | 퍼센트로 표시한 물리적 메모리 사용량 |
| VSZ | 사용 중인 가상 메모리의 크기 (KB) |
| RSS | 사용 중인 물리적 메모리의 크기 (KB) |
| STAT | 프로세스 상태 (1.3절) |
| START | 프로세스 시작 시간 |

*표 5. `ps aux`의 추가 출력 정보*

`aux`는 `-ef`처럼 시스템의 모든 프로세스에 대한 자세한 정보를 출력하며, TTY가 `?`인 프로세스는 터미널과 연결되지 않은 프로세스(데몬, 커널 스레드 등)이다. 특정 명령의 프로세스를 찾을 때는 `ps -ef | grep 명령`처럼 `grep`과 연결해서 사용한다.

> **주의:** `-u`와 `-f`를 묶을 때는 `ps -fu user1`처럼 `-u`가 `-f` 뒤에 와야 한다. `ps -uf user1`로 쓰면 `-u` 바로 뒤의 `f`를 사용자 이름으로 해석하여 `error: user name does not exist` 오류가 발생한다.

### 2.2 pgrep: 패턴으로 프로세스 검색

`pgrep`은 지정한 패턴과 일치하는 프로세스를 찾아 PID를 출력한다. 형식은 `pgrep [옵션] [패턴]`이다.

| 옵션 | 기능 |
|------|------|
| `-x` | 패턴과 정확히 일치하는 프로세스의 정보를 출력한다. |
| `-n` | 패턴을 포함하고 있는 가장 최근 프로세스의 정보를 출력한다. |
| `-u 사용자 이름` | 특정 사용자에 대한 모든 프로세스를 출력한다. |
| `-l` | PID와 프로세스 이름을 출력한다. |
| `-t term` | 특정 단말기와 관련된 프로세스의 정보를 출력한다. |

*표 6. pgrep의 주요 옵션*

```bash
$ pgrep -x bash                      # 이름이 정확히 bash인 프로세스의 PID
2096
$ pgrep -l bash                      # PID와 명령 이름 출력
2096 bash
$ ps -fp $(pgrep -x bash)            # pgrep의 결과를 ps에 넘겨 자세한 정보 검색
UID          PID    PPID  C STIME TTY          TIME CMD
user1       2096    2095  0 13:18 pts/0    00:00:00 -bash
$ ps -fp $(pgrep -u user1 bash)      # user1의 bash 프로세스만 검색
```

### 2.3 top: 실시간 프로세스 모니터

```bash
top                     # 대화형 프로세스 모니터
```

`top`은 현재 실행 중인 프로세스의 정보를 주기적으로 출력한다. 화면 상단에는 가동 시간, 사용자 수, 부하 평균(7.2절), 상태별 프로세스 수(Tasks), CPU와 메모리, 스왑 사용량 같은 요약 정보를, 하단에는 각 프로세스의 정보를 출력한다.

| 항목 | 의미 | 항목 | 의미 |
|------|------|------|------|
| PID | 프로세스 ID | SHR | 프로세스가 사용하는 공유 메모리의 크기 |
| USER | 사용자 계정 | %CPU | 퍼센트로 표시한 CPU 사용량 |
| PR | 우선순위 | %MEM | 퍼센트로 표시한 메모리 사용량 |
| NI | Nice 값 | TIME+ | CPU 누적 이용 시간 |
| VIRT | 프로세스가 사용하는 가상 메모리의 크기 | COMMAND | 명령 이름 |
| RES | 프로세스가 사용하는 물리 메모리의 크기 | | |

*표 7. top의 출력 정보*

**top 대화형 명령어:**

| 키 | 동작 |
|-----|--------|
| `q` | 종료 |
| `k` | 프로세스 종료 (PID 입력) |
| `r` | 프로세스 우선순위 변경 |
| `P` | CPU 사용률 기준 정렬 |
| `M` | 메모리 사용률 기준 정렬 |
| `u` | 지정한 사용자의 프로세스만 출력 |
| `n` | 출력하는 프로세스의 개수 변경 |
| `Enter`, `Space` | 화면을 즉시 다시 출력 |
| `1` | 개별 CPU 코어 표시 |
| `h` | 도움말 |

*표 8. top의 대화형 명령*

### 2.4 pstree: 프로세스 트리

```bash
pstree                  # 프로세스 트리 표시
pstree -p               # PID 표시
pstree -u               # 사용자 전환 표시
pstree user1            # 특정 사용자의 프로세스 표시
```

GNOME 데스크톱 환경에서는 그래픽 도구인 시스템 감시(System Monitor)로도 프로세스 목록과 자원 사용량을 확인하고 프로세스를 종료할 수 있다.

## 3. 포그라운드 및 백그라운드 프로세스

### 3.1 프로세스 실행

```bash
# 포그라운드 (기본값)
command                          # 완료될 때까지 터미널을 점유

# 백그라운드
command &                        # 백그라운드에서 실행
nohup command &                  # 백그라운드에서 실행, 로그아웃 후에도 유지
```

사용자가 입력한 명령이 실행되어 결과가 출력될 때까지 기다리는 방식으로 처리되는 프로세스를 **포그라운드 프로세스**라고 한다. 명령의 마지막에 `&`(앰퍼샌드)를 붙여 백그라운드로 실행하면 명령의 처리가 끝나는 것과 관계없이 곧바로 프롬프트가 출력되어 다른 작업을 계속할 수 있다. 이렇게 처리되는 프로세스를 **백그라운드 프로세스**라고 하며, 한 터미널에서 여러 프로세스를 동시에 실행할 수 있다.

### 3.2 작업 제어

**작업 제어(job control)** 는 한 터미널에서 동시에 여러 프로세스를 실행하고 관리하는 기능이다. C셸에서 처음 개발되어 4.1BSD 커널에 포함되었고, 이후 본셸 계열에도 도입되어 대부분의 유닉스 셸과 Linux 셸이 제공한다. 작업 제어 도구가 관리하는 프로세스를 **작업(job)** 이라고 하며, 포그라운드 프로세스는 포그라운드 작업, 백그라운드 프로세스는 백그라운드 작업이 된다. 작업 제어는 포그라운드와 백그라운드 사이의 작업 전환, 작업 일시 중지, 작업 종료를 말한다.

```bash
jobs                             # 백그라운드 작업 목록
jobs -l                          # PID 포함 목록
fg %1                            # 작업 1을 포그라운드로 전환
bg %1                            # 작업 1을 백그라운드에서 재개
Ctrl+Z                           # 포그라운드 작업 일시 중지
Ctrl+C                           # 포그라운드 작업 종료
```

`jobs [%작업 번호]`는 백그라운드 작업을 모두 보여 주고, 작업 번호를 지정하면 그 작업의 정보만 보여 준다. 작업 번호 자리에는 `%번호` 외에 `%+` 또는 `%%`(작업 순서가 `+`인 작업), `%-`(작업 순서가 `-`인 작업)를 쓸 수 있다.

| 항목 | 출력 예 | 의미 |
|------|---------|------|
| 작업 번호 | `[1]` | 백그라운드로 실행할 때마다 순차적으로 증가한다 (`[1]`, `[2]`, `[3]`, ...). |
| 작업 순서 | `+` | `+`는 가장 최근에 접근한 작업, `-`는 그 바로 전 작업, 공백은 그 외의 작업이다. |
| 상태 | `Running` | 실행 중(Running), 정상 종료(Done), 비정상 종료(Terminated 등), 일시 정지(Stopped)를 표시한다. |
| 명령 | `sleep 100 &` | 백그라운드로 실행 중인 명령이다. |

*표 9. jobs 명령의 출력 정보*

| 명령 | 기능 |
|------|------|
| `Ctrl+Z` | 포그라운드 작업을 중지한다 (종료가 아니라 잠시 중단하는 것이다). |
| `bg %작업 번호` | 작업 번호가 가리키는 작업을 백그라운드 작업으로 전환한다. |
| `fg %작업 번호` | 작업 번호가 가리키는 작업을 포그라운드 작업으로 전환한다. |

*표 10. 작업 전환 명령*

포그라운드 작업을 백그라운드로 보내려면 `Ctrl+Z`로 일시 중지한 다음 `bg`를 실행한다. 작업 번호를 생략하면 작업 순서가 `+`인 작업이 대상이 된다.

```bash
$ sleep 100                      # 포그라운드로 실행
^Z                               # Ctrl+Z로 일시 중지
[1]+  Stopped                 sleep 100
$ bg %1                          # 백그라운드로 전환
[1]+ sleep 100 &
$ jobs
[1]+  Running                 sleep 100 &
$ fg                             # 다시 포그라운드로 전환
sleep 100
```

포그라운드 작업은 대부분 `Ctrl+C`를 입력하면 종료되며, 종료되지 않으면 다른 터미널에서 PID를 검색하여 `kill` 명령으로 강제 종료한다. 백그라운드 작업은 `kill %작업 번호`로 종료한다.

### 3.3 nohup: 끊김 방지

백그라운드 작업을 실행한 터미널이 종료되거나 사용자가 로그아웃하면, 작업에 전달되는 SIGHUP 시그널 때문에 실행 중이던 백그라운드 작업도 함께 종료될 수 있다. 로그아웃한 다음에도 작업이 끝날 때까지 실행해야 하면 `nohup` 명령을 사용한다. `nohup`은 SIGHUP을 무시하도록 하여 명령을 실행한다.

```bash
nohup long_running_script.sh &
# 출력은 기본적으로 nohup.out에 기록됨
nohup command > output.log 2>&1 &
```

> **참고:** bash는 `huponexit` 옵션이 꺼져 있는 기본 설정에서 `exit`로 로그아웃할 때 백그라운드 작업에 SIGHUP을 보내지 않는다. 그러나 터미널 창을 닫거나 SSH 연결이 끊기면 SIGHUP이 작업에 전달되므로, 작업을 확실히 유지하려면 `nohup`을 쓴다.

출력 파일을 지정하지 않으면 `nohup: ignoring input and appending output to 'nohup.out'` 메시지와 함께 실행 결과가 현재 디렉터리의 `nohup.out` 파일에 저장된다. 예를 들어 `nohup find / -name passwd > pw.dat 2>&1 &`을 실행하고 `exit`로 로그아웃해도 `find`는 계속 실행되며, 검색 결과와 오류 메시지가 모두 `pw.dat`에 저장된다.

## 4. 시그널과 프로세스 제어

### 4.1 주요 시그널

**시그널(signal)** 은 프로세스에게 무언가 발생했음을 알리는 간단한 메시지이다. 무엇이 발생했는지는 미리 정의된 상수로 나타내며, 시그널은 번호로 구분되고 이름을 가진다. 시그널을 받은 프로세스는 기본적으로 종료되지만, 시그널에 따라 정지하거나 계속 실행하기도 한다. `kill -l`은 전체 시그널의 번호와 이름을 출력한다.

| 시그널 | 번호 | 이름 | 기본 동작 | 설명 |
|--------|--------|------|---------------|-------------|
| SIGHUP | 1 | Hangup | 종료 | 터미널과 연결이 끊어짐 |
| SIGINT | 2 | Interrupt | 종료 | Ctrl+C |
| SIGQUIT | 3 | Quit | 코어 덤프 | Ctrl+\\ |
| SIGKILL | 9 | Kill | 종료 | 포착하거나 무시할 수 없음 |
| SIGALRM | 14 | Alarm | 종료 | 알람(타이머)에 의해 발생 |
| SIGTERM | 15 | Terminate | 종료 | 정상 종료 (`kill`의 기본값) |
| SIGSTOP | 19 | Stop | 정지 | 포착할 수 없음 (Ctrl+Z와 유사) |
| SIGTSTP | 20 | Terminal Stop | 정지 | Ctrl+Z가 보내는 시그널 (포착 가능) |
| SIGCONT | 18 | Continue | 계속 | 정지된 프로세스 재개 |
| SIGUSR1 | 10 | 사용자 정의 | 종료 | 커스텀 시그널 |
| SIGUSR2 | 12 | 사용자 정의 | 종료 | 커스텀 시그널 |

*표 11. 주요 시그널*

> **참고:** 시그널 번호는 x86, ARM 같은 일반적인 Linux 아키텍처 기준이다. 일부 아키텍처에서는 SIGSTOP, SIGCONT, SIGUSR1 등의 번호가 다르므로, 스크립트에서는 번호보다 `-STOP`, `-CONT`처럼 이름을 쓰는 편이 안전하다.

### 4.2 kill: 시그널 전송

`kill` 명령은 지정한 시그널을 프로세스에게 보내며, 형식은 `kill [-시그널] PID...`이다. 시그널을 생략하면 15번(SIGTERM)을 보낸다. SIGTERM을 받은 프로세스는 관련된 파일들을 정리하고 종료하지만, 종료되지 않는 프로세스도 있다. 이때는 9번(SIGKILL)으로 강제 종료한다.

```bash
kill PID                         # SIGTERM (15) 전송 - 정상 종료
kill -9 PID                      # SIGKILL (9) 전송 - 강제 종료
kill -HUP PID                    # SIGHUP (1) 전송 - 설정 리로드
kill -STOP PID                   # 프로세스 일시 중지
kill -CONT PID                   # 프로세스 재개
kill -l                          # 모든 시그널 이름 나열

# 이름으로 종료
killall process_name             # 해당 이름의 모든 프로세스 종료
pkill -f "pattern"               # 패턴과 일치하는 프로세스 종료
```

예를 들어 터미널 1에서 `man` 명령을 실행해 둔 상태에서 터미널 2에서 `ps -fp $(pgrep -x man)`으로 PID를 찾고 `kill -9 PID`를 실행하면, 터미널 1의 `man`이 종료된다.

- **pkill**은 PID가 아니라 프로세스의 명령 이름(CMD)으로 프로세스를 찾아 종료한다. 예를 들어 `pkill man`은 이름이 `man`인 프로세스를 모두 종료하며, 이후 `pgrep -x man`을 실행하면 아무것도 출력되지 않는다.
- **killall**도 명령 이름으로 프로세스를 찾아, 그 이름으로 실행 중인 모든 프로세스를 한 번에 종료한다. 일반 사용자는 자신이 소유한 프로세스만 종료할 수 있다.

### 4.3 프로세스 우선순위

```bash
# 조정된 우선순위로 실행 (-20~19, 낮을수록 높은 우선순위)
nice -n 10 command               # 낮은 우선순위로 실행
nice -n -5 command               # 높은 우선순위로 실행 (root 필요)

# 실행 중인 프로세스의 우선순위 변경
renice 10 -p PID                 # 우선순위를 10으로 설정
sudo renice -5 -p PID            # 높은 우선순위로 설정
```

nice 값은 `top`의 NI 열에 표시된다. 일반 사용자는 nice 값을 올려 자신의 프로세스의 우선순위를 낮출 수만 있고, 낮추는 것(우선순위를 높이는 것)은 root만 할 수 있다.

## 6. 예약 작업 (cron과 at)

### 6.1 crontab: 반복 작업

`crontab` 명령은 정해진 시간에 반복 실행할 작업을 담은 사용자별 crontab 파일을 관리한다. 형식은 `crontab [-u 사용자 ID] [옵션] [파일명]`이다.

```bash
crontab -e                       # 현재 사용자의 crontab 편집
crontab -l                       # 현재 사용자의 crontab 나열
crontab -r                       # 현재 사용자의 crontab 삭제
sudo crontab -u user1 -e         # 다른 사용자의 crontab 편집
```

**crontab 형식:**

```text
* * * * * command
│ │ │ │ │
│ │ │ │ └── 요일 (0-7, 0과 7 = 일요일)
│ │ │ └──── 월 (1-12)
│ │ └────── 일 (1-31)
│ └──────── 시 (0-23)
└────────── 분 (0-59)
```

*그림 2. crontab 항목의 여섯 필드*

crontab 파일에는 여러 작업을 저장할 수 있으며 한 줄에 하나의 작업을 설정한다. 한 줄은 분, 시, 일, 월, 요일, 작업 내용의 여섯 항목으로 구성되고, 각 항목은 공백 문자로 구분한다. 요일은 0이 일요일, 1이 월요일, 6이 토요일이며, Linux의 cron은 7도 일요일로 받아들인다. 항목의 값이 `*`이면 해당 항목의 모든 값을 뜻한다. 예를 들어 `30 23 1 * * /usr/bin/ls -l ~user1 > ~user1/cron.out`은 월 항목과 요일 항목이 `*`이므로 매월 1일 23시 30분에 지정한 작업을 실행한다.

**예시:**

```bash
# 매분 실행
* * * * * /path/to/script.sh

# 매일 오전 2시 30분에 실행
30 2 * * * /path/to/backup.sh

# 매주 월요일 오전 8시에 실행
0 8 * * 1 /path/to/weekly.sh

# 매월 1일 자정에 실행
0 0 1 * * /path/to/monthly.sh

# 5분마다 실행
*/5 * * * * /path/to/check.sh

# 월-금 오전 9시에 실행
0 9 * * 1-5 /path/to/work.sh
```

- `crontab -e`는 기본적으로 환경 변수 `VISUAL` 또는 `EDITOR`에 지정된 편집기를 사용한다. vi로 편집하려면 먼저 `EDITOR=vi; export EDITOR`를 실행한다.
- 사용자의 crontab 파일은 `/var/spool/cron/crontabs` 디렉터리에 사용자 이름으로 생성된다. 내용은 `crontab -l`로 확인한다.
- `crontab -r`은 자신의 crontab 파일을 삭제한다. 시스템 관리자가 특정 사용자의 crontab을 삭제하려면 `crontab -u user1 -r`처럼 사용자 ID를 지정한다.

`crontab` 명령의 사용은 `/etc/cron.allow`와 `/etc/cron.deny`로 제한한다.

- `/etc/cron.allow` 파일이 있으면 이 파일에 지정된 사용자만 `crontab` 명령을 사용할 수 있다.
- `/etc/cron.allow` 파일이 없고 `/etc/cron.deny` 파일이 있으면, `/etc/cron.deny`에 계정이 없는 사용자만 사용할 수 있다.
- 두 파일이 모두 없으면 시스템 설정에 따라 시스템 관리자만 사용할 수도 있고 모든 사용자가 사용할 수도 있다.
- 두 파일이 모두 있으면 `/etc/cron.allow`의 내용이 적용되고 `/etc/cron.deny`는 무시된다.

### 6.2 at: 일회성 작업

`at` 명령은 예약한 명령을 정해진 시간에 한 번 실행한다. 형식은 `at [옵션] [시간]`이며, Ubuntu에는 기본으로 설치되어 있지 않으므로 `apt install at`으로 설치한다. 실행 결과를 메일로 받으려면 메일 시스템도 설치되어 있어야 한다.

```bash
at 10:00                         # 오늘 오전 10시에 예약
at now + 30 minutes              # 30분 후에 예약
at 2:00 AM tomorrow              # 내일 오전 2시에 예약
atq                              # 대기 중인 at 작업 나열
atrm job_number                  # at 작업 삭제
```

```bash
$ at now + 1 hour
at> /path/to/script.sh
at>                             # Ctrl+D를 눌러 완료
```

`at`을 실행하면 `warning: commands will be executed using /bin/sh` 메시지와 함께 `at>` 프롬프트가 나타난다. 실행할 명령을 입력하고 `Ctrl+D`를 누르면 `<EOT>`가 표시되고 `job 2 at Sun Dec 19 16:50:00 2021`처럼 작업 번호와 실행 시각이 출력되어 예약이 완료된다. `at 10:00`처럼 시각만 지정했는데 그 시각이 이미 지났으면 다음 날 같은 시각으로 예약된다. 시간은 다음과 같이 다양하게 지정할 수 있다.

- `at 4pm + 3 days`는 지금부터 3일 후 오후 4시에 작업을 수행한다.
- `at 10am Jul 31`은 7월 31일 오전 10시에 작업을 수행한다.
- `at 1am tomorrow`는 내일 오전 1시에 작업을 수행한다.
- `at 10:00am today`는 오늘 오전 10시에 작업을 수행한다.

| 옵션 | 기능 |
|------|------|
| `-l` | 현재 실행 대기 중인 명령의 전체 목록을 출력한다 (`atq`와 같다). |
| `-r 작업 번호`, `-d 작업 번호` | 실행 대기 중인 명령 중 해당 작업 번호를 삭제한다 (`atrm`과 같다). |
| `-m` | 출력 결과가 없더라도 작업이 완료되면 사용자에게 메일로 알려 준다. |
| `-f 파일` | 표준 입력 대신 실행할 명령을 파일로 지정한다. |

*표 12. at의 주요 옵션*

예를 들어 `at -m 0730 tomorrow`, `at 10:00 pm`, `at 8:15 am May 30`처럼 쓸 수 있다. `atq`는 현재 사용자가 등록한 작업 목록을 보여 주며, root가 실행하면 모든 사용자의 작업을 보여 준다. `at`으로 생성된 작업 파일은 `/var/spool/cron/atjobs` 디렉터리에 작업 번호에 따라 생성되는데, 이 디렉터리는 daemon 그룹만 읽을 수 있으므로 내용을 보려면 `sudo`를 써야 한다.

`at` 명령의 사용은 `/etc/at.allow`와 `/etc/at.deny`로 제한한다. `/etc/at.allow`는 사용이 허용된 사용자를 저장하며 필요할 때 만들어야 하고, `/etc/at.deny`는 사용이 금지된 사용자를 저장하며 기본적으로 존재한다.

- `/etc/at.allow` 파일이 있으면 이 파일에 지정된 사용자만 `at` 명령을 사용할 수 있고, `/etc/at.deny`는 무시된다. 따라서 두 파일에 모두 들어 있는 사용자도 `at`을 사용할 수 있다.
- `/etc/at.allow` 파일이 없으면 `/etc/at.deny`에 지정된 사용자를 제외한 모든 사용자가 `at` 명령을 사용할 수 있다. `/etc/at.deny`가 빈 파일이면 모든 사용자가 사용할 수 있다.
- 두 파일이 모두 없으면 root만 `at` 명령을 사용할 수 있다.

### 7.2 uptime과 부하 평균

```bash
$ uptime
10:30:00 up 15 days, 3:22, 2 users, load average: 0.15, 0.10, 0.05
#                                                   ^^^^  ^^^^  ^^^^
#                                                   1분   5분   15분
```

부하 평균(load average)은 실행 중이거나 CPU를 기다리는 프로세스의 평균 개수이며, Linux에서는 디스크 I/O를 기다리는 `D` 상태의 프로세스도 포함한다. 단일 코어 시스템에서 1.0은 CPU를 100% 활용한다는 뜻이고, 코어가 n개이면 n.0이 100% 활용에 해당한다.

## 점검 문제

1. **ps 옵션 유형:** `ps -ef`, `ps aux`, `ps --pid 1`의 옵션은 각각 어떤 유형인가? 또 `ps -fu user1`은 동작하지만 `ps -uf user1`은 오류가 나는 이유는 무엇인가?

   <details>
   <summary>정답</summary>

   `ps -ef`는 `-`로 시작하는 유닉스(SVR4) 옵션, `ps aux`는 `-` 없이 쓰는 BSD 옵션, `ps --pid 1`은 `--`로 시작하는 GNU 옵션이다. `-u`는 바로 뒤에 사용자 이름을 인수로 받으므로 `-fu user1`에서는 `user1`이 사용자 이름이 되지만, `-uf user1`에서는 `f`가 사용자 이름으로 해석되어 `error: user name does not exist` 오류가 발생한다.

   </details>

2. **작업 제어 추적:** `sleep 100`을 실행하고 `Ctrl+Z`를 누른 뒤 `bg %1`, `sleep 200 &`, `jobs`를 차례로 실행했다. `jobs`의 출력을 쓰고, 이어서 인수 없이 `fg`를 실행하면 어떤 작업이 포그라운드로 오는지 쓰라.

   <details>
   <summary>정답</summary>

   `jobs`는 `[1]-  Running  sleep 100 &`와 `[2]+  Running  sleep 200 &`를 출력한다. 가장 최근에 시작한 작업 2가 작업 순서 `+`, 그 전 작업 1이 `-`가 된다. 인수 없는 `fg`는 작업 순서가 `+`인 작업을 대상으로 하므로 `sleep 200`이 포그라운드로 온다.

   </details>

3. **좀비와 고아:** 좀비 프로세스와 고아 프로세스의 차이를 설명하고, 좀비 프로세스가 많이 쌓이면 어떤 문제가 생기는지 쓰라.

   <details>
   <summary>정답</summary>

   좀비 프로세스는 이미 실행을 마쳤지만 부모가 종료 상태를 수집하지 않아 프로세스 테이블에 남아 있는 자식 프로세스이고, 고아 프로세스는 아직 실행 중인데 부모가 먼저 종료된 자식 프로세스이다. 고아는 1번 프로세스(`systemd`)가 입양하여 계속 실행된다. 좀비는 CPU와 메모리를 거의 쓰지 않지만 프로세스 테이블의 항목을 차지하므로, 많이 쌓이면 테이블이 부족해져 새 프로세스를 만들지 못할 수 있다.

   </details>

4. **부하 평균:** 4코어 시스템에서 `uptime`이 `load average: 6.00, 3.50, 1.00`을 출력했다. 세 값의 의미와 시스템 상태를 해석하라.

   <details>
   <summary>정답</summary>

   세 값은 각각 최근 1분, 5분, 15분 동안의 부하 평균이다. 코어가 4개이므로 4.00이 100% 활용에 해당한다. 최근 1분의 6.00은 실행 가능한 프로세스가 코어 수보다 평균 2개 많아 일부가 기다리고 있다는 뜻이고, 15분 평균 1.00에서 5분 평균 3.50, 1분 평균 6.00으로 커졌으므로 최근 들어 부하가 빠르게 증가하고 있다.

   </details>
